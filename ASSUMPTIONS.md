# Ограничения, допущения и необходимые решения

Этот документ фиксирует статус технических решений модуля, разграничение зон ответственности и действия, необходимые для ввода в промышленную эксплуатацию. Пошаговые инструкции приведены в [INTEGRATION.md](./INTEGRATION.md), предварительная оценка стандартов GDPR, E-ITS и EN 301 549 — в [COMPLIANCE.md](./COMPLIANCE.md).

| Вопрос / Компонент | Текущее состояние в модуле | Кто и как закрывает |
|---|---|---|
| Авторизация и роли LIMIS | В модуле реализован компонент [src/AdminAuth.php](file:///c:/Users/kraken/Downloads/limis-feedback/src/AdminAuth.php), поддерживающий два режима: `'standalone'` (пароль для автономной разработки) и `'limis'` (прямая проверка сессии LIMIS на роль `Peakasutaja` с отдачей HTTP 403 Forbidden при нехватке прав). Проверка роли регистронезависима и поддерживает составные идентификаторы. | Разработчик LIMIS задаёт `'auth_mode' => 'limis'` в `config.php` и обеспечивает проброс сессионных cookie LIMIS (`session.cookie_domain = '.narva.ee'`). До этого панель администрирования не открывается публично. |
| Встраивание в страницы LIMIS | Код виджета полностью автономен, синхронизирует язык с `localStorage.getItem('language')` и URL (`?lang=`), поддерживает динамическое переключение в SPA через `window.LimisFeedback` (`setLanguage`, `setPage`, `setCritical`). | Разработчик сайта подключает скрипт и стили на разрешённых публичных страницах и расставляет вызовы `setCritical(true/false)` на ответственных операциях (подача заявлений). |
| Подсчёт страниц и аналитика | `data-page` задаёт системную категорию, сохраняемую в БД. `data-page-key` задаёт уникальный ключ конкретной страницы только для клиентского подсчёта в браузере (на сервер не передаётся). | Для каждой страницы задаётся безопасный статический `data-page-key`. Не помещать в ключ персональные данные, номера дел или токенов. |
| Определение IP за reverse proxy | Реализована функция `client_ip()` с поддержкой доверенных обратных прокси (`trusted_proxies` в `config.php`). Если `REMOTE_ADDR` входит в список доверенных, IP извлекается из `X-Forwarded-For` или `X-Real-IP`. | Администратор инфраструктуры указывает фактические IP-адреса балансировщиков и прокси LIMIS в параметре `trusted_proxies`. |
| Доступность Redis и Rate Limiting | Redis является основным backend лимитирования (3 ответа/час на IP) с fail-closed поведением (HTTP 503 при сбое). При явно отключённом Redis (`redis_enabled => false`) модуль автоматически задействует MariaDB guard с блокировками таблиц. | Эксплуатационная команда мониторит Redis и выбирает стабильный backend (Redis или MariaDB guard) для конкретного экземпляра. |
| Комментарии и персональные данные | Свободный комментарий ограничен 500 символами и сохраняется как введён. В форме размещено явное предупреждение и ссылка на официальные условия обработки данных `https://www.narva.ee/andmekaitsetingimused`. Автоматический фильтр намеренно не используется, так как не даёт надёжных гарантий. | Владелец данных / DPO утверждает сохранение поля комментария, формулировку дисклеймера и регламент обработки случайных персональных данных. |
| Срок хранения данных (180 дней) | Скрипт `bin/purge.php` удаляет ответы старше 180 дней и истёкшие технические записи (guard, nonce). Одновременный запуск блокируется MariaDB advisory lock. | Владелец данных утверждает срок хранения 180 дней. Администратор инфраструктуры настраивает ежедневное задание в Windows Task Scheduler или cron. |
| Принцип наименьших привилегий БД | Схема миграций готова. Подтверждена работа модуля под минимальными привилегиями MariaDB (`SELECT, INSERT, UPDATE, DELETE, LOCK TABLES`). Все избыточные глобальные права и DDL отозваны. | Администратор БД применяет миграцию `001_install.sql` и создаёт runtime-пользователя с проверенным минимальным набором прав. |
| Защита от CSV Formula Injection | Серверный экспорт в CSV экранирует опасные лидирующие символы (`=`, `+`, `-`, `@`, `\t`, `\r`) префиксом апострофа `'`. | Реализовано и покрыто тестами в `tests/admin.test.mjs`. Эксплуатационная команда контролирует права доступа к экспорту. |
| Соответствие GDPR | Ответы минимизированы (без открытого IP, ID пользователя, email или URL). Rate limit хранит HMAC-хэши с TTL 1 час. Добавлена ссылка на условия защиты данных города Нарва. | DPO и контролёр данных утверждают правовое основание, оценку рисков (DPIA при необходимости) и регламент удаления резервных копий. |
| Информационная безопасность E-ITS | В коде применены: PDO с подготовленными выражениями, stateless HMAC-токены, honeypot, fail-closed rate limit, защитные правила `.htaccess` от чтения системных файлов. | Ответственный за ИБ организации определяет категорию информационной системы LIMIS, применимый профиль мер и документирует результаты аудита. |
| Доступность EN 301 549 | Подтверждены 100 баллов Accessibility в Lighthouse 13.4.1, масштабирование 200%/400% без потери контента, озвучивание контекста `<legend>` экранным диктором (Narrator/NVDA), изоляция фокуса (Tab trap) и `inert` для фона. | Специалист по доступности проводит финальное приёмочное тестирование виджета в комплексе с целевыми страницами портала LIMIS. |
| Production-инфраструктура | Конфигурация вынесена в `config/config.php` вне веб-корня. Предусмотрена переменная `LF_CONFIG` для нестандартного размещения. Настроены заголовки `no-store` для токенов. | Администратор сервера настраивает HTTPS, CSP, логирование ошибок (`display_errors = Off`) и мониторинг. |
| Приёмочные и регрессионные тесты | Разработан единый скрипт запуска тестов `bin/test.ps1`, выполняющий 40 автоматических тестов (22 unit + 18 integration) на встроенном runner Node.js без внешних npm-пакетов. | Разработчик запускает `bin/test.ps1` перед каждым обновлением; инженер по приёмке утверждает результаты на staging. |
