# Ограничения, допущения и необходимые решения

Этот файл описывает вопросы, которые нельзя корректно закрыть только изменением кода модуля. Пошаговые действия даны в [INTEGRATION.md](./INTEGRATION.md), предварительная карта GDPR/E-ITS/EN 301 549 — в [COMPLIANCE.md](./COMPLIANCE.md).

| Вопрос | Текущее состояние | Кто и как закрывает |
|---|---|---|
| Настоящая авторизация LIMIS | Административная страница использует отдельный пароль и сама устанавливает `Peakasutaja` в своей сессии. Это тестовый механизм, не проверка роли в LIMIS. | Разработчик LIMIS предоставляет middleware/session/auth-контракт; после этого интегрировать серверную проверку роли на странице и CSV, проверить отрицательные сценарии. До этого не открывать admin route публично. |
| Встраивание в страницы LIMIS | Код виджета работает автономно. Реальные страницы, источник языка и события начала/конца операций неизвестны. | Разработчик сайта подключает скрипт/CSS на разрешённых страницах и тестирует критические операции на staging. |
| Подсчёт страниц | `data-page` задаёт разрешённую категорию, которая записывается в БД. `data-page-key` задаёт уникальный ключ страницы только для подсчёта в браузере. | Для каждой страницы задавать безопасный `data-page-key`; для SPA вызывать `LimisFeedback.setPage(key)`. Не помещать в ключ персональные данные или номера дел. |
| IP за reverse proxy | Rate limit рассчитывается по PHP `REMOTE_ADDR`; заголовок `X-Forwarded-For` не читается. За прокси посетители могут попасть в общий лимит. | Администратор инфраструктуры определяет доверенную цепочку прокси и предоставляет безопасный источник IP; не доверять произвольному клиентскому заголовку. |
| Доступность Redis | По умолчанию Redis — единственный backend лимита; при его сбое API закрывает отправку с HTTP 503. MariaDB guard включается только явным `redis_enabled => false`, динамического переключения нет. | Эксплуатационная команда мониторит Redis и использует отдельные тестовые учётные данные; выберите Redis или MariaDB как стабильную конфигурацию экземпляра. |
| Комментарии и персональные данные | Комментарий сохраняется как введён (не более 500 символов). В форме есть предупреждение, но автоматического фильтра нет. | Владелец данных/DPO утверждает, оставить ли поле, ограничить ли его, внедрять ли обработку/удаление, уведомление и доступ. Текстовый фильтр не гарантирует удаление всех персональных данных. |
| Срок хранения | Очистка задана на 180 дней, но автоматический планировщик не создаётся кодом. Backup, веб-логи и CSV очищаются отдельно. | Владелец данных подтверждает срок и копии; администратор инфраструктуры настраивает и контролирует ежедневный `purge.php` по руководству. |
| GDPR | Код минимизирует поля ответа и не пишет открытый IP в таблицу ответов, но правовое основание, контролёр, уведомление, процессы прав субъектов и backup-политика неизвестны. | Определить на стороне контролёра/DPO; подробная карта и план — `COMPLIANCE.md`. |
| E-ITS | Неизвестны категория и границы LIMIS, применимый набор мер и доказательства соответствия. | Ответственный за информационную безопасность проводит классификацию, оценку риска и проверку мер организации. |
| EN 301 549 | В коде присутствуют некоторые доступные паттерны, но нет полного ручного аудита или проверки с assistive technologies. | Специалист по доступности проверяет модуль вместе с принимающим сайтом, устраняет дефекты и выпускает отчёт. Сертификат данным проектом не выдаётся. |
| Production-инфраструктура | Текущие DSN, HTTPS, CSP, CORS, error log, backup, мониторинг и права на сервере относятся к конкретному размещению. | Администратор среды настраивает это на staging и документирует принятые значения; секреты не помещать в репозиторий. |
| Приёмочные тесты | PHP lint выполнен, но нет полного интеграционного набора и подтверждённой успешной записи в выделенную тестовую БД. | Провести тестирование из раздела 8 `INTEGRATION.md`; зафиксировать среду, результаты, версии и ответственного. |
