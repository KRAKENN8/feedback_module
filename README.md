# LIMIS Feedback Module

Самостоятельный встраиваемый модуль обратной связи для жителей на PHP 8.5 / MariaDB 11 с поддержкой Redis, полностью оформленный в фирменном стиле портала LIMIS (Narva). Включает клиентский доступный виджет опроса, защищённый API приёма ответов, панель администратора с интеграцией ролей LIMIS (`Peakasutaja`), скрипт регламентной очистки и полный набор автоматизированных тестов.

Подробные инструкции по интеграции, настройке окружения, веб-сервера и планировщика задач приведены в [INTEGRATION.md](./INTEGRATION.md). Оценка безопасности и соответствия стандартам (GDPR, E-ITS, EN 301 549) — в [COMPLIANCE.md](./COMPLIANCE.md).

## Требования

- **PHP 8.5** с включёнными расширениями `pdo_mysql` и `mbstring`.
- **MariaDB 11** (рекомендуется отдельная база данных `utf8mb4`).
- **Redis** для атомарного rate limiting (по умолчанию `127.0.0.1:6379`, 3 ответа/час на IP); при отключении Redis автоматически задействуется резервный счётчик MariaDB guard.
- **Node.js** (v18+) для запуска встроенных тестов (`node --test`, без сторонних npm-зависимостей).
- **HTTPS** и размещение файлов конфигурации вне публичного корня веб-сервера.

## Быстрый запуск для проверки

1. **Создайте тестовую базу данных:**
   ```sql
   CREATE DATABASE limis_feedback_proto CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   ```

2. **Примените миграцию схемы:**
   ```sh
   mariadb limis_feedback_proto < migrations/001_install.sql
   ```

3. **Создайте конфигурационный файл:**
   Скопируйте `config/config.example.php` в `config/config.php`. Задайте реквизиты подключения к базе, сгенерируйте надёжный случайный `secret` (не менее 32 байт / 64 hex-символов). Файл `config.php` должен оставаться вне веб-корня и не добавляться в репозиторий.

4. **Задайте пароль администратора для локальной разработки:**
   Сгенерируйте хеш пароля:
   ```sh
   php -r "echo password_hash('ваш_пароль', PASSWORD_DEFAULT), PHP_EOL;"
   ```
   и сохраните его в параметр `admin_hash` в `config/config.php`. По умолчанию включён режим `'auth_mode' => 'standalone'`.

5. **Запустите полный автоматический набор тестов:**
   ```powershell
   powershell -ExecutionPolicy Bypass -File bin/test.ps1
   ```
   Скрипт автоматически проверит синтаксис всех PHP-файлов, статус Redis, выполнит 22 unit-теста виджета и 18 интеграционных проверок API, Redis и безопасности административной панели.

6. **Запустите локальный PHP-сервер:**
   ```sh
   php -S 127.0.0.1:8080 -t public
   ```

7. **Проверьте работу в браузере:**
   - Публичная тестовая страница и виджет: `http://127.0.0.1:8080/`
   - Панель администратора: `http://127.0.0.1:8080/admin/tagasiside.php`

> [!NOTE]
> В автономном режиме (`auth_mode => 'standalone'`) панель использует отдельный пароль (`admin_hash`). Для боевого окружения модуль содержит встроенную поддержку авторизации LIMIS (`auth_mode => 'limis'`), которая проверяет сессионную роль `$_SESSION['active_role'] === 'peakasutaja'` и блокирует доступ с HTTP 403 при нехватке прав. Подробнее — в разделе 6 [INTEGRATION.md](./INTEGRATION.md).

## Как установить на существующий сайт

Краткий порядок установки:

1. **База данных:** настроить отдельную базу MariaDB и выдать пользователю приложения минимальные права (`GRANT SELECT, INSERT, UPDATE, DELETE, LOCK TABLES`).
2. **Схема:** применить `migrations/001_install.sql`.
3. **Конфигурация:** создать рабочий `config/config.php` вне web-root со сгенерированным секретом, настройками Redis и списком доверенных прокси (`trusted_proxies`).
4. **Размещение API:** опубликовать каталог `public/tagasiside/` под тем же origin (или настроить reverse proxy).
5. **Встраивание виджета:** подключить `widget.css` и `widget.js` на разрешённых страницах, указав язык (`data-lang="et"` или `"ru"`), категорию раздела (`data-page`) и уникальный ключ страницы (`data-page-key`).
6. **Критические операции:** при необходимости вызывать `window.LimisFeedback.setCritical(true/false)` для подавления автоматических приглашений во время заполнения важных форм.
7. **Авторизация LIMIS:** переключить `'auth_mode' => 'limis'` в `config.php` для сквозной проверки роли `Peakasutaja` из сессии LIMIS.
8. **Регламентная очистка:** настроить ежедневный запуск `bin/purge.php` через планировщик ОС (Windows Task Scheduler / Linux cron).

Подробное руководство по каждому шагу, настройке reverse proxy/CSP, веб-серверов Apache/Nginx и прав доступа — в [INTEGRATION.md](./INTEGRATION.md).

## Регламентная очистка данных

Скрипт `bin/purge.php` реализует требования GDPR по ограничению сроков хранения:
- удаляет отзывы жителей старше 180 дней;
- очищает истёкшие технические записи счетчиков (`limis_tagasiside_guard`) и одноразовых токенов (`limis_tagasiside_nonce`).

Скрипт запускается через системный планировщик задач под выделенной служебной учётной записью. Одновременный запуск нескольких экземпляров блокируется через MariaDB advisory lock (`GET_LOCK`). Инструкция по настройке планировщика — в разделе 7 [INTEGRATION.md](./INTEGRATION.md).

## Полный откат

Для полного удаления таблиц модуля (например, при деинсталляции):
```sh
mariadb limis_feedback_proto < migrations/001_rollback.sql
```
> [!CAUTION]
> Скрипт безвозвратно удаляет все три таблицы модуля (`limis_tagasiside`, `limis_tagasiside_guard`, `limis_tagasiside_nonce`) и все накопленные данные. Перед запуском обязательно создайте резервную копию базы данных.

## Статус проверок и готовность к внедрению

### Подтверждённые результаты проверок
- **Автоматизированное тестирование:** 40 тестов (22 unit-теста + 18 интеграционных тестов) выполняются успешно через `bin/test.ps1`.
- **Принцип наименьших привилегий БД (Least Privilege):** подтверждена корректная работа под учётной записью только с правами `SELECT, INSERT, UPDATE, DELETE, LOCK TABLES` (DDL и избыточные привилегии отозваны).
- **Доступность (Accessibility / EN 301 549):**
  - Аудит Lighthouse 13.4.1 подтверждает **100 баллов Accessibility**.
  - Проверено масштабирование интерфейса до 200% и 400% без потери содержимого (Reflow / Zoom WCAG 1.4.4 / 1.4.10).
  - Проверена навигация с экранным диктором (Windows Narrator): при перемещении клавишей Tab озвучивается полный контекст вопроса из `<legend>`.
  - Модальное окно изолирует фокус (Tab trap) и переводит фоновый контент страницы в `inert`.
- **Защищённость административной части:**
  - Встроенный компонент `AdminAuth` с автоматической поддержкой ролей LIMIS (`Peakasutaja`), блокировкой с HTTP 403 Forbidden и защитой от CSV Formula Injection при экспорте.
- **Дизайн и оформление:**
  - Стили виджета и тестовой страницы полностью приведены к дизайн-системе LIMIS (цветовая палитра `#24578A`, контрастный фокус `#FFD44D`, типографика Montserrat).
  - Ссылка на условия обработки данных обновлена на официальную страницу города Нарва: `https://www.narva.ee/andmekaitsetingimused`.

### Действия перед вводом в промышленную эксплуатацию
1. **Подключение сессии LIMIS:** переключить режим на `'auth_mode' => 'limis'` в `config/config.php` и убедиться в передаче активной сессии администратора.
2. **Служебный планировщик:** активировать ежедневное расписание запуска `bin/purge.php` в Task Scheduler / cron.
3. **Согласование с DPO:** контролёр данных / DPO утверждает формулировку уведомления о конфиденциальности и правила обработки открытых комментариев.
4. **Сетевые правила:** администратор настраивает список `trusted_proxies` в `config.php` под конкретные IP-адреса балансировщиков LIMIS.
