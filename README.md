# LIMIS Feedback Module

Самостоятельный модуль обратной связи на PHP/MariaDB для последующего подключения к публичным страницам LIMIS. Подключение к настоящему LIMIS и его аутентификации не выполнено. До production необходимы интеграционные проверки и действия, перечисленные в [INTEGRATION.md](./INTEGRATION.md).

## Требования

- PHP 8.5 с расширениями `pdo_mysql` и `mbstring`.
- MariaDB 11.
- Redis (рекомендуется по ТЗ для rate limiting, поддерживается также Docker `redis:alpine`).
- HTTPS и отдельная база данных для размещения.

## Быстрый запуск для проверки

1. Создайте тестовую базу:

   ```sql
   CREATE DATABASE limis_feedback_proto CHARACTER SET utf8mb4;
   ```

2. Примените схему:

   ```sh
   mariadb limis_feedback_proto < migrations/001_install.sql
   ```

3. Скопируйте `config/config.example.php` в `config/config.php`. Задайте DSN, пользователя и пароль тестовой БД, случайный `secret`. Файл `config.php` должен оставаться вне веб-корня и не добавляться в Git.
4. При необходимости создайте хеш тестового пароля админки командой `password_hash` из `INTEGRATION.md` и задайте `admin_hash`.
5. Запустите локальный PHP-сервер из корня проекта:

   ```sh
   php -S 127.0.0.1:8080 -t public
   ```

6. Откройте `http://127.0.0.1:8080/` для проверки оболочки страниц и виджета. Административная страница находится по адресу `/admin/tagasiside.php`.

**Админка пока использует отдельный пароль и не проверяет роль LIMIS. Не размещайте её публично и не используйте для реальных ответов до подключения штатной авторизации.** Подробности — раздел 6 [INTEGRATION.md](./INTEGRATION.md).

## Как установить на существующий сайт

Краткий порядок:

1. Настроить PHP и отдельную MariaDB базу.
2. Применить `migrations/001_install.sql`.
3. Создать рабочую конфигурацию вне web-root.
4. Разместить `public/tagasiside/` под same-origin URL или настроить reverse proxy.
5. Подключить `widget.css` и `widget.js` на разрешённых страницах, задать язык, категорию и уникальный `data-page-key`.
6. Подключить события критических операций.
7. Перед публикацией заменить тестовую авторизацию админки на проверку `Peakasutaja` из LIMIS.
8. Настроить ежедневный запуск `bin/purge.php` и проверить его на тестовой БД.

Полные инструкции по каждому шагу, планировщику Windows/Linux, проверкам, конфигурации proxy/CSP и авторизации — в [INTEGRATION.md](./INTEGRATION.md). Предварительная оценка GDPR, E-ITS и EN 301 549 и перечень требуемых действий — в [COMPLIANCE.md](./COMPLIANCE.md).

## Очистка данных

`bin/purge.php` удаляет ответы старше 180 дней и истёкшие записи защиты. Скрипт сам не запускается: необходимо настроить Windows Task Scheduler, cron или systemd timer. Есть подробная инструкция, проверка кода завершения и журналов в разделе 7 [INTEGRATION.md](./INTEGRATION.md).

Срок 180 дней и его применение к backup, журналам и экспортированным CSV должен утвердить владелец данных.

## Откат

Сначала сделайте резервную копию и подтвердите базу/схему, затем выполните:

```sh
mariadb limis_feedback_proto < migrations/001_rollback.sql
```

Этот скрипт удаляет все три таблицы модуля вместе с их данными; он не предназначен для частичной очистки.

## Структура

`public/` — web-root; `src/` — общие PHP-функции; `config/` — секреты; `migrations/` — SQL-схема; `bin/` — CLI-обслуживание; `tests/` — автоматизированные проверки. Описание каждого файла — в [INTEGRATION.md](./INTEGRATION.md).

## Проверки и известные ограничения

- Запуск тестов описан в разделе 8 [INTEGRATION.md](./INTEGRATION.md). Используются встроенные тестовые средства Node.js, npm-пакеты не нужны. Набор не отправляет валидный отзыв и не записывает ответы в БД.
- Последний запуск 20 ноября 2026 г.: Node.js 26.13.1 и PHP 8.4/8.5; 31 тест пройден (15 unit-тестов виджета/A11y, 10 проверок API, 6 тестов админки и защиты CSV), ошибок нет.
- Успешная запись валидного отзыва в отдельную тестовую БД, конкурирующий rate limit, сетевые/БД-сбои, административная интеграция с LIMIS и автоматическое выполнение очистки не подтверждены.
- В свободный комментарий можно ввести персональные данные; автоматического фильтра нет.
- Сертификация или подтверждение соответствия GDPR, E-ITS или EN 301 549 не проводились и не могут быть выданы по одному репозиторию. См. [COMPLIANCE.md](./COMPLIANCE.md).
